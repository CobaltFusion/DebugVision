Overall usage

DebugVision collects log lines from one or more sources and shows them in one or more views. Every line gets a line number, a time stamp, the process ID and the process name of whoever sent it.

  • Sources (Log > Sources...): on Windows, OutputDebugString is captured by default. You can also tail files, capture the output of a program (File > Run...), listen on UDP or TCP, or connect to the Sysinternals DebugView agent. Dropping a log file on the window opens it; dropping an executable or script runs it as a process source.
  • Views are tabs (File > New View, Ctrl+N). Each view has its own filters, so you can watch the same log in different ways.
  • Filters (View > Filters..., F5) are regular expressions or plain text. Their types are: Include, Exclude, Highlight, Token (colors the matching text), Stop and Track (scrolling), Once, Clear, Beep and Bookmark. The quickest way to make one is to select text in the view and press Ctrl+H (highlight), Ctrl+I (include), Ctrl+E (exclude) or Ctrl+K (token).
  • Finding text: Ctrl+F, then F3 for the next match and Shift+F3 for the previous one.
  • Bookmarks: Ctrl+F2 toggles a bookmark, F2 and Shift+F2 jump between bookmarks.
  • Pausing: Pause (or Ctrl+Shift+P) stops capturing temporarily. Log > Clear Log (Ctrl+Shift+X) empties the log.
  • Saving: File > Save Log saves everything in DebugView++ .dblog format, Save View only the filtered lines and Save Selection only the selected ones. File > Save Configuration saves the views, filters and sources to a .json file.

Help > User Manual opens this page. Your views, filters, sources and window layout are saved when DebugVision closes.

Command line

debugvision [options] [logfile | settings.json]

All options are optional. Without any, DebugVision starts with the sources, views and filters of the previous session. Sources given on the command line are added for this session only and are not saved in the settings. An option that needs a value takes it from the next argument, so put quotes around values that contain spaces. An unknown option or an invalid value is reported in a message box.

Options

-h, /h, --help, /?
Opens this manual in your web browser, writes a short summary of the options to standard output, and exits without starting DebugVision.
--min, -min, /min
Starts with the window minimized. When Options > Hide When Minimized is on, DebugVision starts as an icon in the system tray (not on macOS).
--source <spec>
Adds a source for this session. <spec> is a source type, optionally followed by a colon and comma-separated key=value parameters, for example udp:port=2020 or file:path=app.log,startAt=end. Parameters you leave out get their default. The option can be given more than once. See Source specifications for all types and parameters.
--udp <port>
Listens for log lines on UDP port <port> on all network interfaces. Each datagram is split into lines. This is short for --source udp:port=<port>.
--file <path>
Tails a file: shows its current content, then follows lines appended to it. Truncation and rotation (the file being replaced) are handled, and the format and encoding are detected automatically. This is short for --source file:path=<path>.
--settings <file>
Uses <file> instead of the default settings file, both to load the settings at startup and to save them on exit. If the file does not exist yet, DebugVision starts with default settings and creates it. This makes it easy to keep separate setups, for example one per project.
logfile
Loads a log file once (it is not followed; use --file for that). Plain text, DebugView++ .dblog and Sysinternals DebugView .log files are recognized; the original time stamps and process names are kept for the last two. Only one log file can be given.
settings.json
An argument ending in .json is used as the settings file, the same as --settings settings.json.
Standard input
When data is piped or redirected into DebugVision, it is captured as a source as well, for example myprogram | debugvision.

Source specifications

The format is type:key=value,key=value,.... List values (such as program arguments) are separated by semicolons. Boolean values accept true/false, 1/0, yes/no and on/off. dvcli --list-sources lists the types and their defaults.

Parameters of every source

ParameterMeaning
nameThe name shown in Log > Sources.
encodingHow bytes are decoded into text: auto (default, detects a BOM and UTF-16), utf-8, utf-8-or-legacy (UTF-8, with a fallback to the legacy code page for each line that is not valid UTF-8), legacy, utf-16le, utf-16be.
charsetThe legacy code page used by legacy and utf-8-or-legacy; empty means the system default.
autonewlineEnds a line that has no newline when no more data follows (default true), as Log > Auto Newline does.

Source types

TypeParameters (default)Description
outputdebugstring scope (local) Windows only: captures OutputDebugString output. scope is local (programs in your session), global (services and other sessions; requires running as administrator) or both.
file path, tail (true), startAt (beginning), format (auto) Reads a file. With tail=true new lines are followed. startAt=end skips the existing content. format is auto, text, dblog or sysinternals.
process command, args, cwd, restartOnExit (false), restartDelaySeconds (5) Runs a program and captures its standard output and standard error. args is a semicolon-separated list, cwd the working directory. With restartOnExit=true the program is started again when it exits.
stdin none Data piped into DebugVision. Added automatically when standard input is a pipe or a file.
udp port (2020), bind (0.0.0.0), group, allowedSenders, splitOnNewline (true), processName ([UDP {ip}:{port}]) Receives datagrams. bind is the local address, group a multicast group to join, allowedSenders a semicolon-separated list of sender addresses to accept (empty accepts all). processName is shown in the Process column; {ip} and {port} are replaced by the sender's address and port.
tcp-listen port (2021), bind (0.0.0.0), maxClients (16) Accepts TCP connections and reads lines from every connected client.
tcp-connect host (127.0.0.1), port (2021), reconnectSeconds (5) Connects to a TCP server and reads lines from it, reconnecting after the given delay when the connection is lost.
dbgview-agent host (127.0.0.1), port (2020) Connects to a Sysinternals DebugView agent (dbgview.exe /a), which can capture output on another machine.

Examples

# the previous session, minimized
debugvision --min

# open a saved log
debugvision crash.dblog

# follow a log file, showing only lines written from now on
debugvision --source "file:path=C:\logs\server.log,startAt=end"

# listen on UDP port 2020 and on a multicast group
debugvision --udp 2020 --source udp:port=5000,group=239.1.1.1

# run a program and capture its output, restarting it when it exits
debugvision --source "process:command=python,args=worker.py;--verbose,cwd=C:\work,restartOnExit=true"

# capture the output of a pipeline
myprogram 2>&1 | debugvision

# a separate setup for one project
debugvision --settings project-x.json

Settings

Settings are saved on exit to settings.json in the configuration directory, unless --settings names another file:

PlatformLocation
Windows%APPDATA%\DebugVision\settings.json
Linux$XDG_CONFIG_HOME/debugvision/settings.json, by default ~/.config/debugvision/settings.json
macOS~/Library/Application Support/DebugVision/settings.json

Help > About DebugVision shows the settings file in use.
